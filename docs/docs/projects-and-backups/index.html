Save, back up and move projects

Organize your library, make independent copies, use recoverable Trash and take editable projects to another computer.

Know which kind of copy you need#

  • Project library: the editable projects stored by the app on this computer. Use Ctrl+S to save and wait for the saved state.
  • Project backup: a portable editable copy that you can restore into the app.
  • Exported output: a texture, model, Blender file or resource package for another tool or the game. It is not automatically a complete project backup.

Keep a backup before a major edit, an app update or a computer move. A backup stored only on the same drive does not protect you if that drive fails.

Find and organize your projects#

  1. Press Ctrl+O to open Project library.
  2. Search by project name, folder label or tag. Use Type, Folder, Favorites and Sort to narrow the list.
  3. Use the star beside a project to favorite it. Choose its folder icon to edit Folder label and comma-separated Tags, then select Save project changes.

A folder label organizes the library; it does not move files into a Windows folder. A project can have one folder label and up to ten tags. Clear the search and filters if a project seems to have disappeared.

Rename a project or make a separate copy#

  1. Save the project first. Open the library and choose the pencil icon to Rename, or the copy icon for Duplicate / Save as.
  2. Enter a name starting with a lowercase letter. Use lowercase letters, digits, hyphens or underscores, with no spaces, up to 48 characters.
  3. Select Save project changes. After duplication, open the new entry from the library when you want to edit it; your original editor stays active.

Renaming keeps the same project. Duplication creates an independently editable project with a new identifier. It copies saved design content and library folder/tags, but does not duplicate shared wearable collections or server jobs. Library management actions save pending edits in the active project before changing it.

Linked Blender sources need the selected Blender installation so Studio can make and verify independent packed source copies. A missing file, tool or unsupported external dependency stops duplication with a message. Fix that source and retry; the original source file is not overwritten.

Renaming does not rewrite resource names inside your scripts. Check explicit references after a rename. Folder, tag and favorite metadata belongs to this computer’s library and is not a portable project-design backup.

Move unwanted projects to Trash and restore them#

  1. In the Projects tab, select the checkbox beside one or more entries.
  2. Choose Move selected to Trash and confirm. A single project also has a Trash icon in its row.
  3. To bring it back, open the Trash tab, select the project and choose Restore selected.
  4. Return to Projects and open the restored entry.

Expected result: the project leaves the ordinary list, then returns with its editable contents when restored. Trash keeps the project’s data and recovery history; it does not free disk space. This release has no permanent-delete command, and names in Trash remain reserved.

If a wearable collection, server job or vehicle collection still references the project, Studio identifies the dependency and refuses the move. Remove the named reference first. A vehicle collection and its referenced projects can be selected together; restore its referenced projects before the owner, or restore them together. A blocked item leaves the whole selected batch unchanged.

Keep a version before experimenting#

Open Workspace settings → Project recovery to name and pin a checkpoint before a large edit. A checkpoint stays in this library; an exported backup is a separate file. The recovery and Undo guide explains which option to use, how to restore a selected project and how to discard unsaved edits.

Save an editable backup#

  1. Open the project you want to keep and save its current changes.
  2. Go to Getting started → Your projects → Save project backup…. You can also use the project’s Project backup control where available.
  3. Choose a recognizable filename and a destination you can find again. Keep the supplied backup extension, such as .brickbyscript.
  4. Wait for the message confirming that the backup was saved.

If the app reports that the project is too large or contains invalid data, address that message and create the backup again. A selected filename alone is not proof that a file finished saving.

Reopen it on this or another PC#

  1. Copy the backup to the destination computer and open a compatible version of Brick by Script.
  2. Choose Getting started → Your projects → Open project backup….
  3. Select the saved backup. It is added to the destination library as a new project.
  4. Open the restored copy. Check its name, geometry or code, artwork and imported assets before you remove any original copies.

Expected result: you can continue editing the restored project. Do not rename an ordinary model file to the backup extension; that does not turn it into a Studio project.

Include the files your project depends on#

The current release also offers Project transfer for workflows with linked sources. Review its included and missing-file list. For Blender sources, pack the intended external images in Blender and save before transferring.

Check the restored project on the destination machine. A local path that works on the first PC may be unavailable on the second. Source models, game installations and installed conversion tools can still require separate setup.
