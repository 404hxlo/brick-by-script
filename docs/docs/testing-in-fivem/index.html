Test a resource in FiveM

Test the exact exported resource, record what happened and keep engine validation separate from an editor preview.

Choose the build to test#

A successful conversion or package check means the build passed those checks. It does not prove that a player can enter the interior, wear the accessory or drive the vehicle correctly.

Use a development server you control and keep the exported ZIP with its build report. Follow the installation instructions included with that build. Extract the actual resource folder into the server's resources directory; the manifest should be inside that resource folder, not buried under an extra archive wrapper.

For resource structure, consult the official FiveM manifest reference. Resolve required dependencies and server-console errors before judging the model itself.

Record an interior walkthrough#

  1. In the MLO project's Build and test workspace, find Manual FiveM client tests.
  2. Choose Choose tested ZIP and select the exact resource ZIP installed on the server. The app records its SHA-256 fingerprint.
  3. Enter the FiveM client or game build you are testing.
  4. Join the development server, visit the exported map location and perform each check. Mark it Passed, Failed or Not applicable based on what you actually observed.

Leave unperformed checks as Not tested. An unavailable staircase is different from a staircase that failed its test.

What to check in the game#

  • Enter through the front door and walk through every doorway.
  • Walk on all floors, check wall collision and use each staircase where present.
  • Look through every portal from both directions and move through the entire interior again.
  • Inspect textures, flickering surfaces, furniture and missing props.

For a vehicle, use the spawn name from the build's test-drive instructions. Check steering, doors, collision, materials and LOD changes at distance, then compare handling on a repeatable route. For clothing and jewelry, test on the intended character and look for clipping or deformation during movement.

Save evidence and retest changes#

Write repeatable observations in Walkthrough notes: where the problem occurs, the viewing direction and the steps needed to reproduce it. Select Save walkthrough report to keep the record with that build.

Open walkthrough report previews an existing report. Restoring its results requires the matching ZIP. Choosing a different ZIP starts a new walkthrough; save the old report first if you need it. Editing the building or its placement clears the current test record because the old answers no longer describe the same result.

The app's public release has not established universal in-game acceptance. Your own resource, dependencies and environment still need this validation.
