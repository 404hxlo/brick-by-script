Recover work and use Undo

Choose between Undo, unsaved changes, named checkpoints and backups without confusing what each one keeps.

Choose the kind of recovery you need#

  • Undo / Redo: move backward or forward through recent edits in the running app.
  • Discard unsaved changes: return the current project to its last saved design.
  • Recovery checkpoint: keep a saved version in the local library and restore it as a separate project.
  • Project backup: create an editable file you can keep separately or move to another computer.

Autosave is on by default, so an earlier edit may already be saved. Discard only affects changes that have not been saved. Use recovery or a backup when you need an older saved design.

Choose Save, Discard or Cancel#

When autosave is off and the current project has unsaved edits, switching projects or closing the app asks what to do:

  • Save changes: keep the pending edits and continue.
  • Discard changes: return to the last saved design and continue.
  • Cancel: stay where you are with the unsaved edits still available.

To revert without leaving the project, press Ctrl+K, choose Discard unsaved changes… and confirm. Script Studio also offers this in its project menu. Already saved edits remain saved; there is no earlier version to discard if the app reports no unsaved changes.

Save a named, pinned checkpoint#

  1. Open the project you want to preserve.
  2. Choose Workspace settings → Recovery → Project recovery.
  3. Enter a Checkpoint name, such as “Before changing the fit.” Leave Pin this checkpoint selected if you want to protect it from automatic history cleanup.
  4. Choose Save checkpoint and wait for the confirmation. This saves the open project’s current edits first.

To change an existing point, select it under Saved revisions, edit its name or pin status, and select Save checkpoint details.

Restore the project you actually selected#

  1. Press Ctrl+O and expand Recover an earlier project.
  2. Choose the correct entry in Project to recover, then expand Project recovery.
  3. Select the saved revision or named checkpoint you want.
  4. Choose Restore as new project. Find and open the recovered copy from the library to inspect it.

The original project stays unchanged. Browsing another project’s history does not checkpoint whichever project happens to be open: Save checkpoint is disabled for an inactive project. Open that project first if you want to make a new checkpoint. Restore a project from Trash before browsing its earlier revisions.

Recover an intact checkpoint from a damaged project#

In 0.19.3, damage to the latest project record no longer blocks its intact recovery history. If opening a project reports that its record is damaged, choose Open project library on the startup error screen, or open the library from another working project.

  1. Expand Recover an earlier project and choose the affected project.
  2. Expand Project recovery, select an intact saved revision and choose Restore as new project.
  3. Open the new copy and inspect its editable contents before continuing.

The damaged original stays unchanged. This requires an intact checkpoint and a readable library; it cannot rebuild missing history or repair every kind of database damage. A project in Trash must be restored first, and a damaged checkpoint is still rejected.

Recovery retains editable project data and embedded assets. It does not version linked Blender files. Use Project transfer for a separate backup of supported linked sources.

Understand what history keeps#

Pinned checkpoints are protected from automatic cleanup until you unpin them. Limits are 8 pinned points per project, 128 across the library, and 64 MiB of pinned history. If pinning exceeds a limit, existing checkpoints remain unchanged; unpin an older point or export a backup.

Unpinned history retains up to 12 recent points per project. All history shares a 128 MiB / 256-point library limit, so older unpinned points may be removed as new work is saved. Automatic points preserve the start and latest saved edit in each five-minute window. Naming or pinning the same saved revision does not create another copy of that revision.

Recovery lives in the same local library as the project. Keep a separate project backup or transfer bundle for long-term storage and moving computers.

Keep creator Undo across workspace changes#

Clothing Studio and Jewelry Studio keep separate Undo histories per project during the current app session. You can visit Pack Builder or Fitting and return to Undo or Redo. The history is bounded to 60 edits per creator, 12 recent creator histories and a shared memory budget; older history can be trimmed.

Restarting the app starts a new Undo session. Saved designs and checkpoints persist separately. Discarding a design clears stale creator Undo, so Undo does not silently bring back the edits you chose to discard.
