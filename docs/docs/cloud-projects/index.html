Continue on another PC

Sign in with GitHub, save a private project snapshot and get an independent local copy on your other computer.

What cloud projects do#

Cloud projects are optional snapshots you save deliberately. Editing a local project or enabling autosave does not upload every change. Choose Save to cloud when you want to make the saved project available to your account on another computer.

Get local copy restores a separate local project. It never overwrites an existing local design. Keep editable backups as well; Project transfer remains available without a cloud account.

Sign in with GitHub#

  1. Install the current app on each Windows PC.
  2. Open Workspace settings → Account & cloud.
  3. Choose Continue with GitHub. Finish signing in and reviewing consent in your system browser, then return to the app.
  4. Use the same GitHub account on both computers. Check the account shown before saving or downloading.

You do not create a separate Brick by Script password. If you want to stop, return to the app and choose Cancel sign-in. If GitHub sign-in is unavailable, local editing and project transfer still work.

Save from the first computer#

  1. Save your design and any linked Blender source files.
  2. In Account & cloud, choose the Local project.
  3. For a first upload, leave Cloud destination set to Create a separate cloud project. To add a version to an existing cloud project, select that destination deliberately.
  4. Choose Save to cloud and wait for the saved-version confirmation.

The snapshot includes the saved project, embedded artwork and supported linked Blender sources packed by Project transfer. Only upload files you have permission to store. Save and correctly link sources before packing; missing or unsupported sources can prevent a complete transfer.

Continue on the other computer#

  1. Sign in with the same GitHub account and choose Refresh projects.
  2. Find the project and choose Get local copy.
  3. Choose a local folder for linked source files. Wait while the app downloads, verifies and restores the snapshot.
  4. Under Ready on this computer, open the restored project.

Expected result: a new editable local copy appears. Your previous local projects stay intact. To send later edits back, save this local copy to the cloud destination again.

Recovery checkpoints, collections, account credentials, computer-specific tool paths and installed tools are not transferred as workspace settings. Install and configure Blender or other tools separately on the second computer.

Handle changes from two computers#

If another computer saved a newer cloud version after you selected your destination, the app refuses to replace it silently. Refresh the list and get that version as a local copy to review. Alternatively, choose Create a separate cloud project to keep both versions.

This release has no automatic merge or background sync. The cloud list exposes the current version; it is not a browser for restoring arbitrary older snapshots.

Manage storage and remove cloud copies#

This preview allows 512 MiB of reserved snapshot storage per account. Storage is reserved in 4 MiB chunks, and older saved versions count toward the allowance. A single packed snapshot can be up to 384 MiB, subject to the remaining allowance. A large project can fill the allowance after only a few saves.

Use a cloud project’s Delete control and confirm Delete cloud project to remove that project and its saved cloud snapshots. Local copies on your computers are kept. Download or back up any version you need before confirming. If a deletion is interrupted, retry it.

Clean interrupted uploads releases unfinished uploads older than two hours. It does not delete completed projects or recently active transfers.

Understand privacy and current limits#

Local editing requires no account. When you choose GitHub sign-in, GitHub authenticates you and the app’s hosted Supabase service receives the identity needed for your account, including your email. Selected project snapshots are stored in that hosted service when you choose Save to cloud. Cloud projects are private to the owning account.

The app stores the sign-in on this Windows profile using operating-system encryption. Sign out removes that saved sign-in, while local projects and saved cloud snapshots remain. Signing out is not account or cloud-project deletion.

Real GitHub sign-in, encrypted-session reopening and a hosted script-project upload/restore have been tested between two independent app profiles on one computer. Acceptance on a second physical PC and representative large linked asset transfers is still pending. The app remains an unsigned alpha; a successful cloud transfer does not prove native export or in-game compatibility.
